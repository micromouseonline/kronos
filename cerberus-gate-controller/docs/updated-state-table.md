# Modified Gate Controller State Machine Specification for RATS

This document updates the original 3-gate state machine specification for the Registration And Timing System (RATS) to incorporate two architectural changes:
1. **Edge-Triggered Gates:** Sensor transitions are triggered by initial beam breaks (edge detection) rather than continuous beam obstruction (eliminating reliance on "cleared" signals).
2. **Course Timer Guard:** A boolean flag (`FirstRun`) ensures the course timer starts upon the robot's initial entry into the start cell and is **not** reset on subsequent run attempts during the same overall entry.

Inputs to the gate controller are described as events and can be generated by hardware beam breaks, button presses, or external radio messages.

## Implementation Notes

1. **State 3 (Started) Transition:**
   - In continuous-sensing mode, State 3 waited for the start gate to be cleared.
   - Under edge triggering, State 3 becomes a transient state. On the start gate trigger edge, it dispatches `<TimerState, 3>` and `<C1SplitTime, 0>` to RATS, then immediately advances to **State 4 (Running)**.

2. **State 5 (Finishing) Transition:**
   - In continuous-sensing mode, State 5 waited for the finish gate to clear before returning to **State 1**.
   - Under edge triggering, State 5 dispatches `<TimerState, 5>`, transmits `<C1RunTime, value>` three times for error mitigation, and immediately exits back to **State 1 (Waiting Robot)** (or after a brief software debounce delay).

3. **Course Timer Persistence (`FirstRun` Flag):**
   - **State 9 (New Entry)** initializes `FirstRun = true`.
   - **State 2 (Robot at Start)** checks the flag:
     - If `true`, it sends `<CourseTimeMs, 0>` to RATS to start the entry time counter and sets `FirstRun = false`.
     - If `false` (e.g., following an aborted run where State 4 returned to State 2), it skips sending `<CourseTimeMs, 0>`, keeping RATS's course timer running without disruption.

4. **Hardware Blanking / Debouncing:**
   - Because physical optical beams can produce rapid oscillating edge signals as a robot passes through, firmware should implement a brief lockout/debounce timer (e.g., $100\text{--}500\text{ ms}$) on gate triggers to prevent duplicate state transitions.

5. **RATS State Response Behavior:**
   - Reporting **State 2** causes RATS to reset split times and clear run touches.
   - Reporting **State 4** causes RATS to increment the active run counter.
